### Challenge: The Chain You Already Worked

This challenge does not add a new ticket. It asks you to reread five you already worked this phase, not as five separate tickets, but as one intrusion, in Cyber Kill Chain order. Real attackers do not announce which stage they are on, and a SOC that closes each ticket without ever lining them up against each other never sees the chain at all.

Open your own results from this phase and put these five in order.

1. **The Spray, the Lockout, and the One That Got Through.** Exploitation. Password Spraying ([T1110.003](https://attack.mitre.org/techniques/T1110/003/)) against six throwaway accounts failed everywhere it landed. The quiet success on a service account, with no failure in front of it, is where the real exploitation happened: a weakness turned into an actual way in.
2. **The 2 AM Login.** Exploitation, a second target. A focused run of guesses against one admin account, alex.rivera, succeeded a few minutes later. Password guessing ([T1110.001](https://attack.mitre.org/techniques/T1110/001/)) against a single account is the same tactic as a spray, aimed instead of wide.
3. **The Quiet Beacon.** Installation and Command and Control. A scheduled task (Scheduled Task, [T1053.005](https://attack.mitre.org/techniques/T1053/005/)) kept access working without anyone at the keyboard, which is Installation. The outbound firewall rule it needed to reach outside the firm is the channel, Command and Control, the stage after Installation in the chain.
4. **Lock Every Gate.** Not a stage this attacker reached. A second way onto the domain controller, found and closed during the same review, before anything used it. Breaking a chain before an attacker reaches the next link counts as much as catching them on one they already used.
5. **The Night the Queue Didn't Stop.** Installation again. The first beacon got found and closed, so whoever was behind it tried a second time: a new scheduled task and a new backdoor group membership (Account Manipulation, [T1098](https://attack.mitre.org/techniques/T1098/)), both ways to keep access rather than new ways in.

Two tickets from this phase are missing from that list on purpose: Approved Overnight, or Not? and Baseline a Team, Then Find Who Breaks It. Both looked, for a moment, like they could belong here. Neither did. One was a legitimate sign-in that only sounded like an attack; the other was ordinary privilege creep nobody had reviewed in a year. Real SOC work is full of findings like that, running alongside whatever the real chain is doing, and telling them apart from the chain itself is as much the job as working the chain.

Lined up this way, the chain never reaches Exploitation's neighbors Weaponization or Delivery in a way you can see directly, because a SOC rarely gets a clean look at an attacker's prep before the first sign-in attempt lands. It also never reaches Actions on Objectives, the stage after Command and Control where an attacker finally does something with the access. Twice, it got stopped at Installation and Command and Control first. That is not a gap in the story. It is the story: every stage an attacker does not reach is a stage your team already broke.
